# ClassicMac 2.0.7

> **Known issue:** Quake III's vertical mouse movement is reversed in this
> release. Use ClassicMac 2.0.8 or later.

ClassicMac 2.0.7 restores Quake III Arena Demo's match load and fixes the
reversed vertical mouse axis with changes that strengthen GXMetal for other
classic games as well.

## Quake III enters live play again

- An exact-artifact release bisect found that 2.0.0, 2.0.1, and 2.0.2 load
  Q3DM1 successfully, while 2.0.3 is the first release to stop at
  `AWAITING SNAPSHOT...`.
- A source-level bisect then isolated the regression to `871a390`, the 2.0.3
  dynamic RAVE resource commit. Its immediate predecessor enters the arena;
  that commit faults on the first unbound six-vertex textured draw.
- The snapshot message was a symptom, not a networking failure. Retaining a
  complete second copy of every direct-color texture and bitmap exhausted
  Quake's fixed classic-Mac application heap during the level load.
- Ordinary direct-color resources now upload directly to the host without a
  permanent guest shadow. Dynamic writable backing is allocated lazily only
  when software requests it through `kQANoCopyNeeded`, then retained for later
  read/modify access and dirty-rectangle uploads.

## Correct physical mouse Y

- AppKit reports relative Y using its bottom-left coordinate convention,
  while QEMU and the GXMetal host bridge use positive-down relative axes.
- Cocoa now normalizes that boundary once, before any guest input backend sees
  the event. GXMetal Input continues translating QEMU motion to
  InputSprocket's positive-up element contract, so moving down looks down and
  moving up looks up in Quake III.
- The QEMU build verifies that this normalization remains present.

## Validation

- The exact published 2.0.0 through 2.0.3 bundles established the release
  boundary, and isolated guest-driver builds established the first bad commit
  and the permanent-shadow allocation as the cause.
- With the fixed current engine, QEMU, startup extension, and InputSprocket
  driver, Q3DM1 clears the snapshot boundary, spawns the player, remains live,
  and pitches correctly in both vertical directions.
- The same acceptance run reports no GXMetal queue fault or missing-resource
  diagnostic.
- GXMetal's guest build, eight native protocol/queue/renderer suites, the QEMU
  realization/input handoff test, icon-family verification, and packaged
  Mac OS 9 conformance remain release gates.
