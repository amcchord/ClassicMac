# ClassicMac 2.2.0 beta 2

ClassicMac 2.2.0 beta 2 is a corrective prerelease that restores the native
virtual-machine window while preserving the browser/VNC viewer introduced in
beta 1 as an optional per-machine feature.

## Viewer behavior

- New and existing machines open in a native QEMU Cocoa window by default.
- Turn on **View in browser (VNC)** during machine creation or under the
  machine's **Viewer** settings to use the private browser display on its next
  start.
- Native-window machines do not create a VNC socket, WebSocket listener, or
  browser server.
- Browser-viewed machines remain bound only to local Unix and `127.0.0.1`
  endpoints, and their noVNC page continues across a Power Mac restart.
- **Show Window**, **Open in Browser**, the live screen preview, and restart
  behavior all follow the machine's saved viewer choice.

Existing `.classic` packages from beta 1 do not contain a viewer preference,
so beta 2 intentionally opens them in a native window. Enable the toggle once
if browser viewing is preferred for a particular machine.

## GXMetal payload

The GXMetal 2.2 beta 1 driver, Tools CD, conformance apps, game-sweep tooling,
and graphics fixes are unchanged in this corrective app release. Beta 2 is the
recommended build for continued manual game testing because it includes all
beta 1 progress without making VNC the only interactive display path.

## Validation

- 39 Swift tests cover native Cocoa arguments, optional loopback VNC arguments,
  viewer preference persistence, legacy-config migration, and the existing VM
  launch contract for both machine families.
- Release assembly verifies the signed app and both helper bundles.
- The release verifier requires Cocoa, VNC-over-WebSocket, and ClassicMac's
  native-window input options in both bundled QEMU executables.
- The full GXMetal native, Metal, Python, guest, and QEMU regression gates from
  beta 1 remain applicable because their payload is byte-identical.

This remains a prerelease: the ten-game GXMetal qualification sweep is still
in progress, and the compatibility ledger distinguishes full representative
gameplay evidence from partial routes and pre-3D application blockers.
