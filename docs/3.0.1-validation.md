# ClassicMac 3.0.1 validation

## Scope

The new-machine wizard recommends downloading configured Mac OS 9, while
retaining manual Quadra/Power Mac setup in the same sheet. New Power Mac
disks default to 32 GiB. The hosted OS 9 template receives a fresh 32 GiB
filesystem, and the importer distinguishes compressed bytes, expanded bytes,
guest capacity, and an enforced initial storage budget.

Existing machines are not resized. Emulator and guest GXMetal sources are
unchanged from the qualified 3.0.0 release. Published 3.0.0 assets are immutable.

## Template qualification

Evidence is retained in `output/3.0.1/template/`.

- Raw capacity: 34,359,738,368 bytes (32 GiB).
- HFS+ filesystem capacity: 34,354,298,880 bytes; the boot wrapper and Apple
  partition/driver records account for the remaining approximately 5.4 MB.
- The freshly assembled disk occupied 118,702,080 host bytes before startup.
- Exact released engine boot: Finder at 28.176 seconds, 30-second idle/input
  check, and clean guest shutdown passed (`32gb-full-boot.txt`).
- GXMetal 2.3.0 conformance passed (`gxmetal-conformance.txt`).
- The public source contains audited Apple system files, selected bundled
  apps, and GXMetal. Its preferences were generated by the fresh guest's own
  initial startup; source user preferences/documents/free space were excluded.
- Finder Get Info reports capacity 31.99 GB and available 31.28 GB
  (`guest-capacity-info-verified.png`). Tools-disabled startup, input, and
  clean shutdown also passed (Finder at 26.922 seconds; `boot-summary.json`).
- A custom Get Info/no-Tools harness disturbed its own later pointer
  assertion. Its "minimal devices" option also removed the NDRV loader and
  tablet, which does not match the app's Tools toggle. The corrected check
  removed only Tools and passed; no guest crash or product defect was found.

## App, storage, and distribution

The final combined Swift suite passed 102 tests, with no failures or skips
(`test-evidence/swift-final.log`). Three packaging tests and three template
geometry/sparse/temporary-file-ownership tests passed. A bounded independent
review found no remaining actionable issues.

Storage checks cover understated budgets, content preservation, nonzero
chunk boundaries, a zero-filled 512-byte EOF tail, legacy catalog fallback,
and actual allocation after close. APFS can fill small sparse gaps when a
file closes; the importer explicitly preserves those holes. Unknown or
unqualified filesystems keep the conservative full-capacity space check.

A full optimized Swift import of the real archive preserved the exact disk
hash and used 124,780,544 bytes for its 32 GiB disk. The same import-plus-hash
verification fell from 124.20 to 30.63 seconds after replacing a byte-by-byte
empty-space scan with a system buffer comparison. This is a local measured
comparison, not a promised download/install time on every Mac.

The native wizard was inspected for selected/recommended download, in-sheet
navigation, Back, manual setup, default 32 GB hardware, and successful manual
creation/dismissal. The manually created disk uses 16,384 bytes for 32 GiB
capacity. Screenshots are in `output/3.0.1/ui/`. The final app loaded the public
32 GiB catalog and completed its download/import, dismissed the wizard, and
selected the new machine with the expected OS provenance and capacity.

The hosting preflight retained the original catalog locally and in a private
server backup. The new versioned archive is published, and the catalog was
promoted atomically after archive verification. HTTPS/range checks passed;
see the [hosting record](operations/classicmac-downloads.md). The old
catalog/archive remain the rollback reference.

The public wizard download's disk hash exactly matched the qualified source;
its disk occupied 124,780,544 bytes and its complete initial package occupied
124,788,736 bytes (`test-evidence/public-ui-import.json`). The final native
app started that downloaded machine to Finder and shut it down through the
app command. Both HFS+ headers confirm clean unmount afterward
(`test-evidence/public-ui-boot-shutdown.json`). Ad-hoc native coordinate clicks
did not provide a reliable visible input assertion; the established guest
boot/input harness supplies the input qualification above.

All test emulator processes stopped. Both temporary UI machines were removed
using Remove from Library, keeping their evidence files. The three original
library entries remain. Existing installed app and user disk capacities are
unchanged.

The final app and DMG are Developer ID signed, Apple-notarized, stapled, and
accepted by Gatekeeper. Mounted-DMG release verification passed, including
the macOS 15 runtime-library closure checks. Runtime app source ends at
`fb8d6295e4483da4c145d7982048c7ab5f3512f1`; later commits contain records only.
